# Архитектурные решения (ADR) — индекс

Одна строка на ADR, не длиннее 300 символов; полный текст — в `docs/decisions-full.md` (поиск по `ADR-NNN`).
Статус: `active` или `superseded by ADR-MMM`.

- **ADR-008** (active): Защиты оркестратора ограждают от ошибок модели, но не от временных правок внутри хода; от prompt injection защищает песочница раннера, недоверенные проекты гонять в ОС-песочнице.
- **ADR-009** (active): `commandProblem` разворачивает обёртки команд, нормализует бинарники по `basename` и отклоняет опасные формы; вариант «Всегда» предлагается только для известных инструментов.
- **ADR-010** (active): Механические защиты: коммиты без переименований, `EXECUTOR.md` всегда в `Frozen`, защищённые конфиги только для high-risk, SIGKILL зависшим процессам, блок опасных флагов git.
- **ADR-011** (superseded by ADR-032): Русские `SKILL.ru.md` и `EXECUTOR.ru.md` — эталон правил, рабочие файлы переводятся на английский в S5; раскладка `--init` по умолчанию — `compact`.
- **ADR-012** (active): Порядок дорожной карты S1–S5: безопасность, развязка с переходом на `compact`, адаптеры, декомпозиция ядра, английский перевод и публичный MIT-репозиторий.
- **ADR-013** (active): `parseAgentResponse` принимает ответ `agy` только если валидный корневой JSON стоит строго в конце, и отклоняет обрезанный внешний JSON.
- **ADR-014** (active): Раскладка не задана в `DEFAULTS` и определяется по пути конфига; `--init` пишет `compact`, этот репозиторий остаётся на `classic`.
- **ADR-015** (active): Конфиги оркестратора и файлы правил скилла безусловно заморожены для Исполнителя (`alwaysFrozenFiles`); правки скилла делает Архитектор вручную.
- **ADR-016** (active): В `BASE_COMMANDS` остаются 12 стек-нейтральных команд, `runners.mjs` единообразно блокирует запрещённые скрипты npm/pnpm/yarn/bun/make/just.
- **ADR-017** (active): Структурный журнал `events.jsonl` — основной источник для `statusText` и `watch`, плюс кроссплатформенный поиск бинарников по `PATH`.
- **ADR-018** (active): URL webhook хранится только вне репозитория, уведомление передаёт закрытый набор токенов без `stopReason`, команд и путей.
- **ADR-019** (active): Единый контракт адаптеров, проверка коммитов при сбое Исполнителя и побайтная сверка слепка охраняемых неотслеживаемых файлов в `installGuards`/`verifyGuards`.
- **ADR-020** (active): Адаптер Claude Code (`runner: "claude"`): запуск `claude -p` с JSON-схемой и `dontAsk`, проверка `permission_denials`, правила allow/deny на Bash/Edit/Write.
- **ADR-021** (active): Белый список файловых целей в правилах разрешений со сравнением по реальным путям и отдельный файл настроек `claude` на каждый проект.
- **ADR-022** (active): Для `claude` включена песочница, запреты `.git` сужены до config/hooks/info, чтение каталога скилла открывается через `additionalDirectories`.
- **ADR-023** (active): Генераторы промптов вынесены в `prompts.mjs`, `suggestedCommand` вычисляется только для безопасного пути, файлы скилла защищены переносимо.
- **ADR-024** (active): Пять поведенческих eval-сценариев (`evals.mjs`) оцениваются по состоянию временного git-репозитория и отказам разрешений, живой замер двухэтапный A0 → A1.
- **ADR-025** (active): Прямое чтение вне `workDir` блокируется в PATH-обёртках `grep`, `ls`, `wc`, `node --test` и `git diff`, `git --no-index` запрещён.
- **ADR-026** (active): Живой транскрипт `claude` читается через `--session-id`, `SKILL.md` декомпозирован со справочниками в `references/`.
- **ADR-027** (active): Харнесс живых замеров evals: изолированная раскладка, fail-closed проверки чистоты хоста, статус ERROR с повтором, положительные проверки `arch:` коммитов.
- **ADR-028** (active): `realGit` обязан быть абсолютным путём, сессия продолжается при отказе разрешения до `maxPermissionPrompts`, ходы eval логируются.
- **ADR-029** (active): Закоммиченные планы в фикстурах eval, общее правило формы команды в `autoRefusalPrompt`, пошаговая запись `results.md`, понятные ошибки `agy`.
- **ADR-030** (active): Рабочее ядро скилла и все промпты оркестратора переведены на английский с двуязычными парсерами; README сжаты до 25 КБ, добавлены LICENSE (MIT) и CHANGELOG.
- **ADR-031** (active): Оркестратор сам детерминированно запускает `Verify` (бэктики, таймаут, предпроверка команд), сбои идут в доработку без вызова LLM Архитектора.
- **ADR-032** (active): Дублирующие русские копии правил в папке скилла отменены: источник правил — английские файлы, для людей остаются `README.ru.md` и `README.en.md`.
- **ADR-033** (active): Детерминированная самопроверка `--self-check` на диапазоне `<base>..HEAD`: обходы, пустые catch, таймеры в тестах, монотонность, `fix-frozen`, `WAIVER`.
- **ADR-034** (active): Фиксация `Commit: <sha>` в `results.md`, сверка доказательств eval и `red-check` эталонных тестов до коммитов `T-NNN:`.
- **ADR-035** (superseded by ADR-075): Совещательный read-only аудит плана `--audit-plan` моделью другого семейства с обязательным разбором каждого `blocker`/`important`.
- **ADR-036** (active): Минимальная версия Node для оркестратора — 22 (`MIN_NODE`), тесты обязательно прогоняются на Node 22 и 24.
- **ADR-037** (active): Скилл автономен от хост-проекта: тесты и пути без литерала папки скилла, проверки установки в `localChecks`, настраиваемый `redCheckCommand`. docs/plans/2026-10-31-stage-1-host-decoupling.md
- **ADR-038** (active): Готовность для сторонних проектов (v3.28/1.8): больше нейтральных команд чтения, исправлено возобновление после эскалации. docs/plans/2026-10-31-stage-2-readiness-for-others.md
- **ADR-039** (active): Механический контроль коммитов и модели вне цикла: `hooks.mjs`, `commit-msg`, `--check-task`, запрет `--no-verify`. docs/plans/2026-10-31-stage-3-stranger-acceptance.md
- **ADR-040** (active): Предпубликационная гигиена: сканер пустых `catch` в тесте упаковки, `fetch-depth: 0` в CI, корневые `README.md` и `LICENSE`. docs/plans/2026-10-31-stage-4-pre-publication.md
- **ADR-041** (active): Запрет молчаливой подстановки модели: `--init` пишет пустые модели, шаблон субагента без `model`, `--check` требует выбора. docs/plans/2026-10-31-cycle-16-human-model-choice.md
- **ADR-042** (active): Установка скилла в один шаг, на первом запуске Архитектор спрашивает модель Исполнителя; добавлен eval `first_run_no_executor_model`. docs/plans/2026-11-03-cycle-17-one-step-install.md
- **ADR-043** (active): Командный режим включается только `"team": true`, правила в `references/team.md`, шаблон CI, проверки поддерживаются и на Linux. docs/plans/2026-11-03-cycle-18-team-mode-v1.md
- **ADR-044** (active): Личный gitignored-оверлей конфига для полей окружения, цепочка выбора модели Исполнителя, `alwaysFrozen` включает workflow и CODEOWNERS. docs/plans/2026-11-03-cycle-18-team-mode-v1.md
