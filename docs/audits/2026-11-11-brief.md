## 2. Общий вывод

- **Архитектура верная.** Все три аудита сходятся: связку «контракты + замороженные тесты + детерминированная механика» сохранять, полное перепроектирование не нужно.
- **Критических дефектов для доверенного репозитория нет.** Для недоверенного содержимого связка C-13, C-14, C-18 критична.
- **Механические гарантии слабее заявленных.** Они теряются при перезапуске цикла (C-07), при почти правильном формате плана (C-01) и при high-risk задаче без эталонных тестов (C-04).
- **Канал «человек подтверждает» обходится.** Агент может ответить на собственный запрос разрешения (C-13).
- **Защиты — ограждение, а не граница безопасности.** Документация говорит обратное (C-18).
- **Вторичные подсистемы дали большую часть дефектов:** права `agy`, самообновление, выбор модели, миграция раскладки, аудит плана.
- **До закрытия P0** автономный цикл не запускать без присмотра, на недоверенном содержимом и на `agy` в нескольких проектах сразу.

## 5. Ограничения проекта, которые задевают исправления

- **Потолок 400 строк на модуль.** Уже у границы: `adapters/claude.mjs` 396, `run.mjs` 395, `selfcheck.mjs` 395, `feed.mjs` 395, `adapters/agy.mjs` 395, `evals.mjs` 394, `update.mjs` 393, `hooks.mjs` 389, `permissions.mjs` 387, `guards.mjs` 386, `cli.mjs` 381, `check.mjs` 372, `mechanics.mjs` 361. Почти каждое исправление требует сначала выделить модуль.
- **Не уплотнять код в однострочники.** Дефект C-06 сидит именно в такой строке (`run.mjs:39`).
- **Ядро `SKILL.md`:** 32 906 байт при потолке 34 816, запас 1 910 байт. Новые правила оплачиваются удалением дублей.
- **Правка правил** (`SKILL.md`, `EXECUTOR.md`, `references/*.md`) идёт по `MAINTAINING.md` §1: версия, оба README, `CHANGELOG.md`, `package.json`. Правка `EXECUTOR.md` поднимает политику до 1.9 и требует побайтной копии в корне.
- **Тесты закрепляют текущее поведение.** Русские строки вех — в `events.test.mjs`, `feed.test.mjs`, `commit-hooks.test.mjs`; фразы промптов — в `prompts-en.test.mjs`, `field-permissions-prompts.test.mjs`. Смена ожидаемых значений идёт через `arch: fix-frozen` с согласия пользователя.
- **Монотонность массивов конфига** (`selfcheck.mjs:324–327`) не даёт убрать шаблон из `bypassPatterns`. Путь изменения шаблонов нужно спланировать заранее (C-27).
- **Зоны высокого риска** сейчас не включают `ask.mjs`, `plan.mjs`, `run.mjs`, `check.mjs`, `cli.mjs`, хотя дефекты C-01, C-07, C-13 находятся там (Р-9).
- **Платные запуски** (живые проверки `agy`, eval-замеры) — только с явного согласия пользователя.
- **Самоприменение.** Циклы исполняет тот же оркестратор, который исправляется. До закрытия цикла 2 после любой остановки по нарушению механики сверяй весь диапазон задачи вручную.

## 6. Что не трогать

- Запуск `Verify` оркестратором с `shell: false` и allowlist.
- Блокировку файлов `Frozen` для Исполнителя и предстартовый red-check как идею.
- Изоляцию контекста Исполнителя и минимальный запрос.
- Процесс по уровню риска и точки согласия пользователя.
- Протокол эскалации со слепком `stop.status.txt` и `stop.diff`.
- Три слоя блокировки push и журнал восстановления.
- Адаптер `claude`: отдельный файл настроек вне репозитория и песочница.

## 7. Расхождения между аудитами и непроверенное

- **Цитата А1** о тексте «Mechanical checks … passed» в `prompts.mjs:116` в коде не найдена. Фактический текст формируется в `run.mjs:324–328`; суть находки C-12 верна.
- **Похвала А1** «red-check падает именно по AssertionError» не подтверждается кодом: красным считается почти любой ненулевой выход (C-34).
- **«`npm test` падает из коробки» (А1):** у М набор прошёл 256/256 за 109 с под параллельной нагрузкой. Это нестабильность, а не постоянный отказ (C-30).
- **Минимальная версия Claude Code 2.1.259 (А2)** не проверена; в установленной 2.1.308 флаг есть (C-44).
- **`sandbox-exec` (А1) или `agy --sandbox` (М):** сначала проверить штатный флаг `agy`.
- **Не запускалось ни в одном аудите:** живой цикл с моделями, реальный PR командного режима, семантика `agy --sandbox` и `agy --settings`.
