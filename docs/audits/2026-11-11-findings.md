# Каталог находок сводного аудита `architect` (v3.46 / 1.8)

Дополнение к `docs/audits/2026-11-11-brief.md`. Читай раздел по ID, а не файл целиком.

- **Пути** без префикса даны относительно `.agents/skills/architect/`.
- **Источник:** М, А1, А2 — три аудита (см. бриф §1), с номером находки в исходном отчёте.
- **Статус:** `[В]` — воспроизведено запуском; `[К]` — подтверждено чтением кода; `[Н]` — не проверено.
- **«Требуется»** описывает поведение, а не реализацию: решение остаётся за Архитектором.

## Цикл 1. План и гейты

### C-01 · P0 · HIGH · Парсер плана склеивает и теряет задачи
- **Источник и статус:** М F-05 · [В]
- **Где:** `orchestrator/plan.mjs:6`, `:88–137`; `orchestrator/check.mjs:143`.
- **Наблюдение:** строка `- [ ] **T-002** — Title` не распознаётся как задача; так же ведут себя `- [X]`, `* [ ]`, `T-2a`. Её поля приклеиваются к предыдущей задаче: `Change` расширяется, `Risk`, `Depends on`, `Model` перезаписываются. После приёмки остальных задач цикл завершается словами «Done: all planned tasks accepted» при оставшейся строке `- [ ]`. CRLF даёт 0 задач.
- **Требуется:** похожая на задачу строка, не прошедшая шаблон, — ошибка готовности с номером строки; число литеральных строк задач равно числу распарсенных; CRLF нормализуется; поля после нераспознанного заголовка не присоединяются к предыдущей задаче.

### C-02 · P0 · Уровень риска не валидируется
- **Источник и статус:** М F-05 · [В]
- **Где:** `orchestrator/plan.mjs:92`; `orchestrator/evidence.mjs:252`; `orchestrator/mechanics.mjs:125`.
- **Наблюдение:** `Risk: high (billing).`, `**high**`, `high — RBAC`, `Высокий (деньги)`, `critical` и пустое значение не считаются высоким риском. Red-check и предупреждение о тестах пропускаются молча.
- **Требуется:** закрытый список значений (`low|medium|high`, `низкий|средний|высокий`; регистр и точка в конце допустимы); любое другое значение — ошибка готовности.

### C-03 · P0 · Пункты `Frozen` без бэктиков и каталоги игнорируются
- **Источник и статус:** М F-05 · [В]
- **Где:** `orchestrator/plan.mjs:21–35`, `:75–78`; `orchestrator/check.mjs:149–152`.
- **Наблюдение:** `- tests/a.test.ts — эталон` без бэктиков, вложенные пункты, `tests/` и `tests` без маски защиты не дают. Заголовок `## 3. Frozen` раздел не открывает. Синтаксис масок `dir/*`, `dir/**` в `SKILL.md` не описан.
- **Требуется:** пункт раздела без пути в бэктиках — ошибка; путь, которому не соответствует ни один файл и который не является маской, — ошибка или предупреждение; синтаксис масок описан в `SKILL.md`.

### C-04 · P0 · HIGH · High-risk задача без эталонных тестов не блокируется
- **Источник и статус:** А2 F-01 · [К]
- **Где:** `orchestrator/evidence.mjs:262–276`; `orchestrator/cli.mjs:186–194`; `orchestrator/run.mjs:230`.
- **Наблюдение:** для high-risk задачи без `referenceTests` пишется только `NOT VERIFIED`, и лишь когда файл из `Change` — код внутри `bypassScanPaths`. Цикл стартует, приёмка возможна.
- **Требуется:** готовность `✗` для открытой high-risk задачи с исполняемым кодом в `Change` без эталонных тестов, если нет явной пометки структурной проверки; таблица рисков в `SKILL.md` и механика совпадают.

### C-05 · P1 · Двусмысленность про бэктики и два формата задач
- **Источник и статус:** А2 F-03, М F-05 · [К]
- **Где:** `SKILL.md:178`, `:190`, `:46`, `:95`; `orchestrator/plan.mjs:113–116`.
- **Наблюдение:** шаблон требует путь теста в бэктиках, а self-check перечисляет символ бэктика среди запрещённых «shell-операторов» для `Test cases` и `Verify`. Формат задач для чата (`- **T-NNN** (risk) — goal`) отличается от формата плана и провоцирует C-01.
- **Требуется:** развести «путь или команда в бэктиках» и «запрет подстановки команд»; формат чата явно помечен как непригодный для `PLAN.md`.

### C-06 · P0 · Неверные коды выхода `--repair` и `--write-permissions`
- **Источник и статус:** А1 F-03 · [В]
- **Где:** `orchestrator/run.mjs:39`, `:57–60`; `orchestrator/guards-recovery.mjs:179–191`; `orchestrator/permissions-cli.mjs:63–66`.
- **Наблюдение:** `handleRepairCli` возвращает число, а `run.mjs` проверяет `!res.ok`. В чистом репозитории `--repair` печатает «✓ No leftover…» и выходит с кодом 1. `--write-permissions` игнорирует `ok: false` и выходит с 0.
- **Требуется:** `--repair` — 0 при успехе, 1 при живом PID; `--write-permissions` — 1 при проваленной пост-проверке; тест через запуск `run.mjs` как процесса.

## Цикл 2. Диапазон задачи и приёмка

### C-07 · P0 · HIGH · Механика проверяет ход, а не задачу
- **Источник и статус:** М F-04 · [В]
- **Где:** `orchestrator/run.mjs:262`, `:287`; `orchestrator/mechanics.mjs:116–117`.
- **Наблюдение:** база проверки — `HEAD` на начало раунда. Коммит A `T-001:` ослабил замороженный тест при том же числе утверждений — нарушение, цикл остановился. После перезапуска коммит B в пределах `Change` дал `ok`, `Verify` прошёл с неидемпотентной реализацией. Нарушение A осталось в истории непроверенным.
- **Требуется:** границы `Change`, `Frozen` и обходы проверяются по всем коммитам задачи с её начала; база задачи устойчива к перезапуску и к промежуточным `arch:`-коммитам.

### C-08 · P0 · `--self-check` и `--check-task` не закрывают C-07
- **Источник и статус:** М F-04 · [В]
- **Где:** `orchestrator/selfcheck.mjs:209`, `:252`, `:340`; `orchestrator/hooks.mjs:145–147`.
- **Наблюдение:** коммиты с темой `T-NNN:` исключены из правила `Frozen` и контентных проверок; `--self-check` по диапазону из C-07 дал `ok`. `--check-task` берёт базой последний `arch:`-коммит; если `HEAD` — `arch:`, диапазон пуст.
- **Требуется:** правило «замороженный файл изменён без `arch: fix-frozen`» действует для любого коммита; `--check-task` считает от базы задачи.

### C-09 · P0 · Приёмку в цикле делает модель, и её коммиты не ограничены
- **Источник и статус:** М F-08, А1 F-02, А1 F-10 · [В] для `--amend`, [К] для остального
- **Где:** `orchestrator/mechanics.mjs:208–224`; `orchestrator/selfcheck.mjs:348`; `orchestrator/prompts.mjs:122`; `orchestrator/run.mjs:341–344`.
- **Наблюдение:** после `Verify` Архитектор сам правит `PLAN.md` и коммитит. Проверяются только префикс `arch:`, отметка `[x]` и чистое дерево. Он может закоммитить код без повтора `Verify`; тема `arch: plan…` освобождает от `fix-frozen`; `git commit --amend -m "arch: accept T-001"` проходит shim и стирает коммит Исполнителя.
- **Требуется:** по Р-2 отметку и коммит приёмки делает оркестратор, Архитектор в цикле не пишет. Иначе: коммиты ревью трогают только `PLAN.md`, база — предок `HEAD`, `arch: plan` в цикле не освобождает от `fix-frozen`.

### C-10 · P1 · Удаление тестов Исполнителем видно только в конце цикла
- **Источник и статус:** А1 F-04 · [К]
- **Где:** `orchestrator/run.mjs:343`.
- **Наблюдение:** пост-ревью self-check считает от `archBase`, то есть после коммита Исполнителя. Удалённый тест в незамороженном файле из `Change` всплывает только на финальном `--self-check`.
- **Требуется:** счётчики тестов и утверждений сверяются по диапазону задачи до приёмки.

### C-11 · P1 · `PLAN.md` в `Change`: цикл разрешает, PR-гейт запрещает
- **Источник и статус:** А1 F-09 · [К]
- **Где:** `orchestrator/run.mjs:288`; `orchestrator/cli.mjs:345–350`; `EXECUTOR.md:10`.
- **Наблюдение:** `run.mjs` снимает нарушение «modifies PLAN.md», если `PLAN.md` вписан в `Change`; `--check-task` и `EXECUTOR.md` запрещают это безусловно.
- **Требуется:** единое правило по Р-7.

### C-12 · P1 · Сводка механики для ревьюера утверждает больше, чем проверено
- **Источник и статус:** А1 F-04, М F-04 · [К]
- **Где:** `orchestrator/run.mjs:324–328`.
- **Наблюдение:** текст «files only from Change; Frozen untouched; no check bypasses in <paths>» относится к одному раунду. Скан обходов пуст, если изменённые файлы лежат вне `bypassScanPaths` (по умолчанию `src`, `tests`).
- **Требуется:** текст называет проверенный диапазон; если ни один изменённый файл не попал в пути скана — «bypass scan skipped», либо скан идёт по изменённым файлам.

## Цикл 3. Подтверждение и git-shim

### C-13 · P0 · HIGH · Агент может ответить на собственный запрос разрешения
- **Источник и статус:** М F-01 · [В]
- **Где:** `orchestrator/ask.mjs:183–221`; `orchestrator/run.mjs:64`, `:194`, `:207–211`; `orchestrator/permissions.mjs:261–262`; `orchestrator/adapters/claude.mjs:35–46`.
- **Наблюдение:** файл `.agent-runs/answer.json` с содержимым `{"id":"T-001-exec-q","answer":"1"}`, положенный до вопроса, принят `askPermission` за 1 мс; цикл записал бы `command(npm install)`. Вопрос, а не авто-отказ, получают `npm install <pkg>`, `npm publish`, `pip install`, `docker run`, `gh pr merge`. Запись в `.agent-runs/` агентам не запрещена.
- **Допущение:** файловый инструмент раннера пишет в игнорируемый каталог; живой ход не запускался.
- **Требуется:** id вопроса содержит случайную часть, известную только процессу оркестратора; существующий ответ удаляется перед вопросом; ответ с чужим id отвергается; комментарий `run.mjs:64` соответствует факту.

### C-14 · P0 · HIGH · Сокращённые длинные опции git обходят shim
- **Источник и статус:** М F-02 · [В]
- **Где:** `orchestrator/guards.mjs:119–139`; `orchestrator/permissions.mjs:113–116`.
- **Наблюдение:** через сгенерированный shim при `AGENT_LOOP=1`: `git grep --open-files-in-page="touch X" hello` — код 0, файл создан; `git commit --no-verif -m …` — коммит создан, pre-commit хук проекта не запускался. Полные формы блокируются.
- **Требуется:** политика по флагам, устойчивая к сокращениям: аргумент, являющийся префиксом запрещённой длинной опции, отклоняется; предпочтителен белый список флагов для `grep`, `commit`, `add`, `diff`, `log`, `show`.

### C-15 · P0 · Shim пропускает `commit --amend`, `add -A` и `-C` вне проекта
- **Источник и статус:** А1 F-02 · [В]
- **Где:** `orchestrator/guards.mjs:119–156`.
- **Наблюдение:** `git add -A` — код 0, в индексе посторонний файл; `git commit --amend -m "arch: accept T-001"` — код 0, в истории остался один коммит; `git -C <чужой репозиторий> log` — код 0, тогда как `diff` даёт 97.
- **Требуется:** `--amend`, `add -A`, `--all`, `-u`, `.` отклоняются в shim; проверка каталога `-C` действует для всех подкоманд.

### C-16 · P1 · `commandProblem` — денилист по первому токену
- **Источник и статус:** М F-02 · [В]
- **Где:** `orchestrator/permissions.mjs:93–131`.
- **Наблюдение:** `xcrun git push --no-verify <url>`, `AGENT_LOOP=0 git push <url>`, `ruby -e …`, `busybox sh -c …` возвращают `null` и уходят вопросом человеку с вариантом «разрешить эту команду». `git push`, `env git push`, `curl`, `rm` получают авто-отказ.
- **Требуется:** префикс `KEY=VALUE` и запуск git или интерпретаторов через обёртки — авто-отказ; для неизвестного бинарника вопрос допустим, но с пометкой «оркестратор не распознаёт команду».

### C-17 · P1 · Зависший `question.json` ломает протокол `--watch`
- **Источник и статус:** М F-13 · [В] суб-аудитом
- **Где:** `orchestrator/feed.mjs:321–325`; `orchestrator/ask.mjs:240–250`; `orchestrator/run.mjs:150`.
- **Наблюдение:** вопрос, оставшийся после убитого цикла, всегда даёт `--watch` код 2. Битый JSON или отсутствие `options` даёт исключение и код 1 вне протокола 0/2/3/4.
- **Требуется:** вопрос действителен только при живом владельце блокировки; ошибка чтения даёт код 3 с причиной.

- **Источник и статус:** М F-03, А1 F-01 · [К]; наличие флага — по `agy --help` 1.5.5

### C-21 · P0 · HIGH · `--write-permissions` портит общий файл настроек `agy`

### C-22 · P1 · Управляющие файлы доступны агенту на запись

## Цикл 5. Надёжность цикла и CLI

### C-24 · P1 · `Verify`: большой вывод диагностируется как таймаут
- **Источник и статус:** М F-07 · [В]
- **Где:** `orchestrator/mechanics.mjs:345–347`; `orchestrator/run.mjs:310–321`; `orchestrator/config.example.json:57`.
- **Наблюдение:** вывод больше 1 МБ дал `kind: "timeout"` через 186 мс; таймаут ведёт в раунд доработки. `npm test` этого репозитория занимает 109–137 с при лимите 120 с.
- **Требуется:** большой вывод не обрывает проверку; переполнение и таймаут различаются; таймаут — остановка с причиной «среда»; лимит по умолчанию пересмотрен.

### C-25 · P1 · Нет штатной остановки цикла
- **Источник и статус:** М F-13 · [К], блокировка — [В] суб-аудитом
- **Где:** `orchestrator/run.mjs:152`; `orchestrator/adapters/agy.mjs:123`; `orchestrator/guards.mjs:268–290`; `orchestrator/guards-recovery.mjs:107–110`.
- **Наблюдение:** обработчик SIGINT/SIGTERM снимает защиты и блокировку, не завершая процесс агента. Захват блокировки неатомарен: в 28 из 30 одновременных попыток успешны обе. Блокировку с PID живого постороннего процесса `--repair` не снимает.
- **Требуется:** команда остановки; сначала завершается агент, затем снимаются защиты; захват атомарен; владелец проверяется не только по PID.
