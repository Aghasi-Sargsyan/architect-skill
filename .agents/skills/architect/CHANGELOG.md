# Changelog

All notable changes to the `architect` skill and its embedded orchestrator are documented in this file.

## v3.27 / 1.8 (2026-10-30 — Cycle S10: Architect Self-Check, Red-Check, and Advisory Plan Audit)
- **Deterministic Architect self-check (`selfcheck.mjs`, `evidence.mjs`, `cli.mjs`, `--self-check`):** Added mechanical checks over Architect commits in `<base>..HEAD` (bypass scan, multiline empty `catch` scan, test timing call ban, unconditional test/assert/config/`eval-fixtures.mjs` monotonicity, `arch: fix-frozen <T-NNN|audit>: ` enforcement after the plan commit, explicit `- WAIVER <sha7>: <rule> — <reason>` handling, and `eval <run-id> @ <sha7>: X/Y PASS` artifact verification).
- **Reference test `red-check` (`plan.mjs`, `evidence.mjs`, `mechanics.mjs`):** Extracted `referenceTests` from backtick paths in `Test cases` (`Тест-кейсы`) that belong to `Frozen`, stripped `NODE_TEST_CONTEXT` in `runTaskVerification` so nested `node --test` processes report non-zero exit codes on Node 20/22+, and verified that new/modified high-risk reference tests fail on assertion before Executor implementation.
- **Advisory cross-model plan audit (`audit.mjs`, `schemas/audit.json`, `references/plan-audit.md`, `--audit-plan`):** Added read-only (`Read`/`Grep`/`Glob` only) plan auditing via Claude Code with post-run git invariance checks, a limit of 1 re-run per cycle base, and mechanical verification that every `blocker`/`important` finding `A-N` is resolved in `PLAN.md`.
- **Interactive session & eval reporting discipline (`SKILL.md` `v3.27`, `references/{auto-review,orchestrator,retro}.md`):** Added pre-commit `HEAD`/`git status --porcelain` verification, mandatory `--self-check` checkpoints, post-review monotonicity/`fix-frozen`/`WAIVER` checks inside the loop, and the `< 5` eval sample reporting rule (`NOT VERIFIED (sample < 5)` without "flake / stochastic noise / regression not confirmed" claims).
- **Node 22+ orchestrator baseline (`ADR-036`, `check.mjs`, `cli.mjs`, `run.mjs`, `MAINTAINING.md`, `references/retro.md`):** Raised the orchestrator minimum runtime to Node 22+ (`MIN_NODE = 22` and pre-config `nodeVersionProblem` check in `main()` across all CLI modes; skill rules and manual Executor handoff remain Node-independent) and standardized dual-version verification on Node 22 and Node 24.

## v3.26 / 1.8 (2026-10-29 — Post-S5 Rule Alignment and Anti-Bypass Hardening)
- **Single English source of truth for rules (`ADR-032`):** Removed redundant Russian rule copies (`SKILL.ru.md`, `EXECUTOR.ru.md`, `references/{auto-review,orchestrator,retro,stacks}.ru.md`) after aligning `EXECUTOR.md` and `references/*.md` 1:1 with them; `SKILL.md`, `EXECUTOR.md`, and `references/*.md` are now the sole rule files while `README.ru.md` and `README.en.md` remain for humans (`skill-s5.test.mjs` enforces that no `*.ru.md` other than `README.ru.md` exists in the skill folder).
- **1:1 alignment of `EXECUTOR.md` (`1.8`) with `EXECUTOR.ru.md`:** Restored full 1:1 parity between English `EXECUTOR.md` and Russian `EXECUTOR.ru.md` (including baseline run reuse rules, post-escalation working-tree resume verification, and Escalation Rule item 3 `global prototype mutation` / «мутация глобальных прототипов»).
- **1:1 alignment of `references/{auto-review,orchestrator,retro,stacks}.md` with `*.ru.md`:** Replaced the abridged/divergent English `references/*.md` files with exact 1:1 translations of the canonical Russian `references/*.ru.md` guides and expanded `orchestrator/skill-s5.test.mjs` to enforce section-level structural and technical-token parity across all bilingual pairs.
- **Global prototype mutation ban & contradictory test-contract escalation (`SKILL.md` `v3.26`, `EXECUTOR.md` `1.8`, `references/auto-review.md`):** Explicitly forbade mutating global objects and built-in prototypes (`String.prototype`, `Object.prototype`, `globalThis`) as Category 1 check bypasses, added an explicit Executor escalation trigger when test contracts / reference tests contradict each other, and added a pre-handoff Architect self-check for non-contradictory `Frozen` tests.
- **Concise chat output & no task-card or skill-diff dumps in chat (`SKILL.md` `v3.26`, `SKILL.ru.md` `v3.26`):** Forbade dumping full `PLAN.md` task cards (`Read`, `Change`, signatures, regexes, `Frozen` test checklists, `Verify` commands), `git diff` blocks of skill files, line-by-line file comparison inventories, and `PASS` tables into chat during Phase 1 or Phase 2; chat summaries are restricted to 1–2 lines per task and 1–3 line conclusions for code/test/eval checks and skill-rule changes.
- **Provenance note (`f5e167b` → `v3.26 / 1.8`):** The global prototype mutation ban in `SKILL.md`, `SKILL.ru.md`, and `EXECUTOR.ru.md`, as well as the `Frozen` reference-test self-check (`SKILL.md`, lines 123 and 158), landed in git earlier in `f5e167b` under the `v3.25` tag alongside edits from a concurrent session; `v3.26 / 1.8` formally versions them and restores the exact `afbb624` semantics in `orchestrator/eval-fixtures.mjs`.
