# Architect (`v0.4`)

Одностраничный скилл для случая, когда одна сильная модель и проектирует, и пишет код. Он держит четыре привычки: согласовать до кода, записать решение, иначе обращаться с рискованным кодом и честно сообщить, что проверено. English guide: [README.md](README.md).

## Что он делает

1. **Согласование до кода.** Модель читает журнал решений и нужный код, предлагает два-три варианта с их ценой и не меняет файлы, пока вы не одобрите один из них. Если ответить некому (вы так сказали, так написано в файле инструкций или в запросе запуска, либо в сессии нельзя задать вопрос), она не ждёт: обратимые решения выполняет и помечает в журнале `unconfirmed`, а дорогие в откате оставляет вопросами в отчёте.
2. **Журнал решений.** Каждое проектное решение записывается в `docs/decisions.md`: одной строкой, если оно обратимо, и короткой записью (что выбрали, что отвергли, почему, когда пересмотреть), если откат дорогой.
3. **Зоны риска.** Там, где ошибка наносит ущерб, который не отменить откатом коммита (деньги, доступы, хранимые данные и миграции, форматы и интерфейсы, на которые опираются другие, конкурентность, персональные данные), тесты с ожидаемыми результатами пишутся до реализации и не подгоняются под код.
4. **Честное завершение.** Работа готова, когда команда проверки запущена и прошла. Упавшая проверка помечается `FAILED`, а всё, что не запускалось, помечается `NOT VERIFIED`.

## Установка

Запускайте в корне своего проекта. Команды можно повторять: повторный запуск обновляет скилл. Они заменяют любой скилл, уже установленный в папку с именем `architect`.

- **Claude Code (`.claude/skills/`):**
  ```bash
  tmp=$(mktemp -d) && git clone --depth 1 https://github.com/Aghasi-Sargsyan/architect-skill.git "$tmp" && mkdir -p .claude/skills && rm -rf .claude/skills/architect && cp -R "$tmp/architect" .claude/skills/ && rm -rf "$tmp"
  ```
- **Codex, Cursor, Gemini CLI, Antigravity (`.agents/skills/`):**
  ```bash
  tmp=$(mktemp -d) && git clone --depth 1 https://github.com/Aghasi-Sargsyan/architect-skill.git "$tmp" && mkdir -p .agents/skills && rm -rf .agents/skills/architect && cp -R "$tmp/architect" .agents/skills/ && rm -rf "$tmp"
  ```

## Обновление

Повторите команду установки для своего агента. Она заменяет папку скилла последней версией из репозитория и больше ничего не трогает: блок правил в вашем `AGENTS.md` и ваш `docs/decisions.md` остаются как есть. Версия блока указана в его заголовке. При следующем запуске скилл сравнивает её со своей и, если ваш блок старше, предлагает заменить его правила, сохранив ваши зоны риска, команду проверки и путь к журналу решений.

Чтобы удалить скилл, удалите его папку.

## Использование

1. Напишите `/architect <что хотите сделать>` (или попросите агента прочитать `SKILL.md` в папке скилла).
2. При первом запуске модель предложит добавить блок из [templates/agents-block.md](architect/templates/agents-block.md) в ваш `AGENTS.md`, `CLAUDE.md` или `GEMINI.md`, уже с зонами риска и командой проверки вашего проекта, которые она нашла в коде. О блоке она спрашивает отдельно от дизайна; проверьте оба поля, прежде чем согласиться. Этот блок держит правила активными в каждой сессии, в том числе там, где вы скилл не вызывали.

## Когда использовать

- **Нужен**, если проект проживёт дольше пары недель, если фича затрагивает данные, доступы или деньги, или если прежние решения начали противоречить друг другу.
- **Не нужен** для прототипа, MVP по готовому образцу, мелкой правки и чисто визуальной работы.
- **Его недостаточно**, когда код пишет более дешёвая модель, когда цикл часами работает без присмотра или когда команде нужен след ревью. Скилл доверяет модели и ничего не проверяет механически.

## Изменения

- **v0.4:** просьба строить больше не пропускает шаг согласования, а на блок правил нужно отдельное «да»; версия блока перенесена из скрытого комментария в его заголовок, поэтому скилл узнаёт свой блок (в том числе старый `architect-lite`) и заменяет его, а не добавляет второй; объявить запуск работающим без присмотра можете только вы, файл инструкций или запрос запуска; если тесты в зоне риска нельзя запустить, модель спрашивает до реализации, а упавшая проверка помечается `FAILED`; решения с пометкой `unconfirmed` поднимаются при следующем запуске с человеком; блок использует путь к журналу решений, принятый в проекте.
- **v0.3:** скилл теперь называется `architect` (раньше `architect-lite`) и живёт в собственном репозитории, поэтому изменились команда установки и команда вызова; в устанавливаемой папке только `SKILL.md` и шаблон блока. Если у вас стоял `architect-lite`, удалите его папку, установите скилл заново и дайте ему обновить блок правил.
- **v0.2:** работа без присмотра больше не останавливается на шаге согласования; зоны риска и команду проверки в блоке модель заполняет по проекту; в блоке появилась строка с версией, и скилл предлагает обновить устаревший блок.
- **v0.1:** первая версия.
