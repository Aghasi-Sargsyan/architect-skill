## Goal / Requirements
Цикл 18: Командный режим v1 (`v3.30 / 1.8`, один Главный Архитектор / техлид + N Исполнителей в Antigravity, Claude Code и Codex через ветки и PR на GitHub):
1. Явный переключатель `"team": true` в общем конфиге (`--init --team`), не меняющий соло-поток и не зависящий от `CI=true`; установка стек-нейтрального шаблона `.github/workflows/team-ci.yml` (`templates/github-team-ci.yml` с `ubuntu-latest`, Node 22 и чтением `fullTestCommand` из конфига проекта); официальная поддержка `--check`, `--check-task` и `--self-check` на Linux с добавлением `ubuntu-latest` в матрицу `.github/workflows/ci.yml` скилла.
2. Поток веток `cycle/<N>` (план и красные `Frozen`-тесты, прямые пуши `arch: accept T-NNN` и `arch: close cycle <N>` от техлида), `task/T-NNN → cycle/<N>` (узкий PR-шлюз `--check-task T-NNN --base origin/cycle/<N>`) и `cycle/<N> → master` (полный тестовый набор + `--self-check`, слияние только через Merge commit). Правила командного режима вынесены в `.agents/skills/architect/references/team.md` с одной ссылкой из `SKILL.md`.
3. Безопасность шлюза `--check-task`: чтение `PLAN.md` из `<base>:PLAN.md` (а не из рабочего дерева ветки задачи), запрет любых правок `PLAN.md` в ветке задачи, расчёт коммитов и diff обходов от `git merge-base <base> HEAD` (корректная работа как на отставшей ветке `task/T-NNN`, так и на синтетическом `refs/pull/N/merge`), fail-closed при неразрешимом `--base` с подсказкой про `fetch-depth: 0`, включение `.github/workflows/**`, `CODEOWNERS` и `*.local.json` в `alwaysFrozen`.
4. Личный gitignored-конфиг (`.architect/config.local.json`, `.agents/orchestrator.local.json`) поверх общего с fail-closed запретом переопределения полей политики; вывод итоговой модели и её источника в `--check` по цепочке `.local.json → общий конфиг → файл агента`; поля `Executor: @<github-ник> · <Окружение> · <Модель>` (отказ оркестратора брать задачу при несовпадении окружения с локальным `runner`) и `Parallel with: T-MMM` с механической проверкой непересечения по `Change`, `Frozen` и `referenceTests`.
5. Корректный разбор истории с merge-коммитами (включая прохождение `--self-check` на `cycle/<N>` в середине цикла с открытыми задачами и несколькими `arch: accept`) и детектор squash-коммитов (признак `(#N)` в теме засчитывается только вместе с другим признаком squash).

## Decisions (ADR)
Актуальный реестр долговечных решений (`ADR-008`…`ADR-042`) хранится в `docs/decisions.md`.
- **ADR-043:** Явный переключатель командного режима (`"team": true`), вынос правил в `references/team.md`, шаблон `templates/github-team-ci.yml` и поддержка Linux для проверок (`v3.30 / 1.8`): (1) командный режим включается только явным полем `"team": true` в общем конфиге проекта (`.architect/config.json` или `.agents/orchestrator.json`), создаваемым через `run.mjs --init --team` вместе с `"fullTestCommand": "npm test"` и копированием `.agents/skills/architect/templates/github-team-ci.yml` в `.github/workflows/team-ci.yml`; соло-режим (`team` не задан или `false`) не меняется, а `CI=true` никогда не включает строгие командные проверки, чтобы локальный прогон всегда совпадал с CI; (2) правила командного режима вынесены в `.agents/skills/architect/references/team.md`, который читается только при `"team": true`, а в `SKILL.md` (`v3.30`) добавлена одна ссылка; (3) детерминированные команды `--check`, `--check-task` и `--self-check` официально поддерживаются на Linux и проверяются на `ubuntu-latest` в матрице `.github/workflows/ci.yml` скилла (запуск цикла агентов остаётся только на macOS).
- **ADR-044:** Личный gitignored-конфиг поверх общего, цепочка выбора модели и расширение `alwaysFrozen`: (1) рядом с общим конфигом поддерживается локальный gitignored-оверлей `.architect/config.local.json` / `.agents/orchestrator.local.json` (`resolveLocalConfigPath` в `layout.mjs`), который может задавать только личные поля окружения (`LOCAL_ALLOWED_KEYS`: `executor`, `architect`, `auditor`, `runner`, `runnerBin`, `agyBin`, `notify`); любые поля политики проекта в `.local.json` отвергаются fail-closed в `validateLocalConfig`; (2) цепочка разрешения модели Исполнителя (`resolveExecutorModelInfo` в `hooks.mjs`, выводится в `--check` как `<model> (source: <path>)`): `.local.json` → общий конфиг → файл агента (`.claude/agents/executor.md` / `AGENTS.md` / `CLAUDE.md` / `GEMINI.md`); (3) в `alwaysFrozenFiles` / `isAlwaysFrozenFile` (`layout.mjs`) добавлены `.architect/config.local.json`, `.agents/orchestrator.local.json`, `.github/workflows/**`, `CODEOWNERS`, `.github/CODEOWNERS` и `docs/CODEOWNERS`, чтобы ветка PR не могла переписать workflow шлюза или правила ревью.
- **ADR-045:** Чтение плана из `<base>`, diff от `merge-base`, merge-история и детектор squash: (1) `runCheckTask` (`cli.mjs`) читает `PLAN.md` из `<base>:PLAN.md` (а не из рабочего дерева), запускает `Verify`-команды задачи из `<base>:PLAN.md` и считает коммиты и скан обходов от `git merge-base <base> HEAD` (`resolveMergeBase` в `git.mjs`), корректно проверяя как отставшую ветку `task/T-NNN`, так и синтетический коммит `refs/pull/N/merge` (`actions/checkout` на `pull_request`), и отвергает любую правку `PLAN.md` в диапазоне задачи; (2) `resolveBaseShaForTask` (`hooks.mjs`) и `resolveSelfCheckBase` (`selfcheck.mjs`) при неразрешимом `--base` завершаются fail-closed (`exit 1`) с подсказкой про `fetch-depth: 0`; (3) `commitsSince` (`git.mjs`) возвращает `parents`, `isMerge` и `body` (для merge-коммитов `files` содержит только конфликтные правки `git show --format= --name-only <sha>`), благодаря чему `--self-check` и `--check-task` проходят на истории с merge-коммитами (включая середину цикла на `cycle/<N>` с открытыми задачами и красными `Frozen`-тестами); (4) `findSquashViolations` (`git.mjs`) отвергает squash-коммиты, засчитывая суффикс `(#N)` в теме только при наличии второго признака squash (маркеры склеенных коммитов в теле, смешивание `- [x] T-NNN:` в `PLAN.md` с кодом задачи в одном не-merge коммите или появление выполненной задачи `- [x] T-NNN:` на `<base>..HEAD` без коммита `T-NNN:`).
- **ADR-046:** Поля `Executor` и `Parallel with` в карточке задачи и проверка параллельных границ: (1) `parsePlan` (`plan.mjs`) извлекает `Executor` (`Исполнитель`) в формате `@<github-ник> · <Окружение> · <Модель (\`id\`)>` (`task.executor`, `task.executorInfo: { handle, env, runner, model }`) и `Parallel with` (`Параллельно с` или `(parallel with T-MMM)` в `Depends on` → `task.parallelWith`); модель из `Executor` никогда не переопределяет `.local.json` или общий конфиг, а при несовпадении `task.executorInfo.runner` с локальным `config.runner` `readiness` отказывается брать задачу; (2) `checkParallelTasks(plan)` (`plan.mjs`, вызывается в `--check`, `--self-check` и `--check-task`) проверяет отсутствие взаимных зависимостей и пересечений параллельных задач по `Change`, `Frozen` и `referenceTests`.
