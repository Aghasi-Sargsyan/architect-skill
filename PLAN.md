# PLAN

## Goal / Requirements
Независимость скилла: развязка от хоста, готовность для других, приёмка на чужих проектах, подготовка к публикации.

### Очередь следующих циклов
- **Правила разрешения эскалаций в `references/auto-review.md`:** (а) если требование недостижимо из-за существующего инварианта — предлагать убрать или изменить требование, а не имитировать состояние в тесте; (б) не использовать моки, завязанные на число или порядок вызовов; (в) `fix-frozen` не уменьшает число проверок — проверка заменяется, а не удаляется; (г) в блоке решения для каждого варианта указывать, какие инварианты и правила он сохраняет или нарушает, и одну сильную сторону нерекомендованного варианта.
- **Технические детали в сообщениях пользователя (`SKILL.md`):** технические детали от пользователя — предложения, а не ADR; если деталь противоречит коду или инвариантам, Архитектор говорит об этом и предлагает альтернативу до реализации (одно возражение, затем решение пользователя).
- **Расширение совещательного аудита другой моделью (`--audit-plan`, `T-048`) на коммиты `arch: fix-frozen`:** перед коммитом `arch: fix-frozen` запускать короткий аудит решения по эскалации другой моделью.
- **Расширение `BASE_COMMANDS` в `permissions.mjs` командами только для чтения с проверкой аргументов:** `git ls-files`, `git grep` (без `-O` / `--open-files-in-pager`), `git blame`, `git ls-tree`, `git merge-base`, `git rev-list`, `git describe`, `git shortlog`, `git stash list`, `git tag -l`, `git branch -a` / `-r` / `--list` (`commandProblem` уже относит их к чтению в диагностике, а в `BASE_COMMANDS` их нет), `git check-ignore`, `pwd`, `which`, `node --version`, `npm ls`; по логам цикла вопросы пользователю были только о `git grep` и `git ls-files`, а `T-011` и `T-021` останавливались из-за нехватки разрешений.
- **Пояснение простым языком к вопросу о разрешении команды (`references/orchestrator.md`):** при передаче `### 🔐 Command Permission` пользователю Архитектор сопровождает вопрос одной строкой простым языком (что делает команда, риск, рекомендуемый ответ), а для незнакомой команды явно указывает «оркестратор не знает эту команду».
- **Контроль ячейки eval `claude:haiku` `high_risk_frozen_test` (`NOT VERIFIED (sample < 5)`):** `eval 2026-10-29T19-28-29-841Z @ cde76a4: 9/10 PASS` (`FAIL claude:haiku high_risk_frozen_test`), `eval 2026-10-30T12-11-59-225Z @ 6e8471c: 1/1 PASS`, `eval 2026-10-30T12-13-40-767Z @ 6e8471c: 1/1 PASS` (по ячейке `claude:haiku` `high_risk_frozen_test` после S5 пройдено 2 из 3 прогонов, `NOT VERIFIED (sample < 5)`; при следующем живом замере — довести выборку до ≥ 5 или завести задачу при повторном FAIL).
- **Замена проверки времени в `shim-speed-s9.test.mjs`:** перевод существующего теста скорости с `performance.now` на структурную проверку (счётчик вызовов/чтений или размер файла).
- **Контроль неизменности `HEAD` хоста во время `runLiveEvals` (`evals.mjs`):** `preStatus` / `postHostStatus` сейчас проверяют только чистоту дерева (`git status --porcelain`), но не сдвиг `HEAD` — фиксировать `Commit:` на старте прогона и сверять с `HEAD` при записи `results.md`.
- **Продолжение после эскалации на грязном дереве и валидный патч `stop.diff` (`check.mjs`, `prompts.mjs`, `run.mjs`, `git.mjs`):** (а) разрешать старт оркестратора после эскалации, когда грязные файлы входят в `Change` текущей задачи и совпадают со слепком эскалации, передавая отчёт об эскалации в `executorPrompt` в соответствии с `EXECUTOR.md:25`; (б) записывать `stop.diff` из `git diff HEAD` без `.trim()` (сейчас `git()` в `git.mjs` обрезает пробелы последней строки контекста, из-за чего `git apply` отклоняет патч с `corrupt patch`) и проверять `git apply --check` в тесте.
- **Отложено по параллельности оркестратора:** worktree-параллельность и пакетное ревью отложены, потому что у рабочих деревьев общие `.git/config` и `hooks`, а `guards` подменяют `remote.*.pushurl` и `pre-push`.
- **Публикация скилла (`E4`):** выгрузка `.agents/skills/architect/` в отдельный публичный репозиторий под лицензией `MIT` с чистой историей и CI-матрицей GitHub Actions на Node 22 и Node 24 — только по отдельной команде пользователя.
